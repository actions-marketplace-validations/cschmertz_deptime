# DT-QA-28 results: how often a real update is to a covered package (2026-11-23)

Protocol: [README.md](README.md), committed in bec6965 before any pull request was collected. Collected on
2026-11-23 from GitHub's search (`share.py collect`), scored once (`share.py score`); the scorer's output is below,
unedited, after the summary.

## Summary

- **C, the decision: 31.7% (95% CI 29.7-33.6%).** Of 2,161 (repository, package) pairs with a major update of a
  library in Dependabot's Python pull requests, 684 are to one of the 53 covered packages. The bar was 60%, so by the
  protocol coverage gets a shortlist (below).
- Every single-package update (A): 21.3%. Major or minor library updates (D): 32.6%. uv projects 21.5%, pip 35.1%.
- **One package stands out:** pillow, with a major update in 338 repositories, half as many pairs as all 53 covered
  packages together (684). The next uncovered package with many major updates is uvicorn (99).
- Much of the rest of the ranking is packages projects usually get through another package and update for a
  security fix (anyio, pyjwt, filelock, requests, idna, multidict): the protocol's known limit that an update isn't
  proof the project's code calls the package.

**Two gaps in the protocol, measured, neither changing the decision:**
- The tooling list missed `uv-build` (a build backend, 30 major pairs) and `pymdown-extensions` (a docs extension,
  13). Left out, C is 32.3% (684/2,118).
- 223 titles were `other`; 66 of them are ordinary updates after an emoji (`⬆ Bump pydantic from ...`), which the
  prefix rule doesn't allow. Parsed, C is 31.6% (687/2,173).

The headline stays the first score, as the protocol fixes.

**For the work of adding them:**
